# One Lambda serves the whole API

Every API operation, including Stripe webhooks, runs in a single API Lambda that routes by method and path, so the in-process API tests exercise the same routing API Gateway reaches and each new operation is only a route and an OpenAPI entry. Scheduled jobs, Step Functions steps and the Assistant get their own functions, reusing the same app code, because they need different triggers, timeouts or permissions; the Assistant's function alone holds Bedrock access and calls the API operations in-process, acting as the person (ADR 0007). This was chosen over one Lambda per operation, which gives finer IAM and per-function metrics but leaves route wiring untested and multiplies cold starts. The tradeoffs are one coarse IAM role over the main table, logs that must name the operation to give per-operation metrics, and cold starts that grow with the bundle. Splitting by area is a CDK-only change, to make when an operation needs different memory, timeout or permissions, or when cold starts become noticeable.
